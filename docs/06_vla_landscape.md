## Part A — The event and the host

### Alloy Robotics (the company)

Alloy Robotics is a **Sydney-founded robotics software startup**, now expanding into the US. It is **not** an arm or humanoid maker: it builds the **"AI Robotics Engineer"** — AI agents that investigate robot *failures* across a fleet, on top of a robotics-native data platform. Its agents ingest logs, telemetry, video and sensor data (MCAP, ROS bags, CSV, Parquet), combine them with engineering context from Slack/Jira/GitHub, and answer plain-language questions like "why did the robot stop?" with findings linked back to missions, timestamps and raw signals. Data lands in managed "Mesh Storage" or the customer's own S3/ClickHouse/Grafana; recordings are stored as Parquet in an open Iceberg catalog. Source (primary): https://usealloy.ai

- **GitHub org** (verified): https://github.com/alloyrobotics — includes `alloy-logger-arduino` (ESP32 "black-box recorder" streaming the whole control loop to Alloy, MIT), `alloy-storage-sdk` (C++ ingest SDK; ESP32/UNO R4 WiFi today, ESP-IDF/MicroPython/Linux/ROS 2 "next"), `alloy-mcp` (MCP server so Claude Code / Codex / Cursor can query fleet data), `tabular2mcap` (GPL-3.0), and — notably for us — **`lerobot2mcap`** (Python, GPL-3.0): converts LeRobot datasets to MCAP.
- **Benchmark**: they run **RoboE-Bench**, a benchmark for "real robotics engineering" scoring AI agents on robotics engineering tasks (linked from their site nav): https://usealloy.ai (see "Benchmark").
- **Funding** (secondary press, consistent across outlets): $8M seed at an $80M valuation, led by Square Peg, announced Aug 2026, with pre-seed backers Blackbird, Airtree and Skip Capital returning; the round also included engineers/leaders from OpenAI, Anthropic, Tesla, Waymo, Halter and Carbon Robotics. Sources: https://itbrief.com.au/story/alloy-robotics-raises-usd-8-million-in-seed-round , https://forbes.com/sites/davidprosser/2026/08/11/alloy-robotics-raises-8-million-to-help-stop-robots-failing/ , https://finance.yahoo.com/technology/ai/articles/alloy-robotics-raises-8m-help-123700855.html
- **Customers named** in press/site: Advanced Navigation, SwarmFarm Robotics, Andromeda, DroneForge, Puralink.

So the "learning loops" framing fits them exactly: their whole pitch is *learn from every run* — capture data, detect anomalies/regressions, investigate failures, feed it back to engineering.

### Can a VLA be trained or even run in 1 day by a small team?

**Trained:** Yes — but only the small ones, on rented NVIDIA GPUs, with realistic expectations. SmolVLA fine-tuning on ~50–200 SO-101 teleop episodes is the documented path (`lerobot-train --policy.path=lerobot/smolvla_base`, HF blog shows exact commands). ConRFT showed VLA RL fine-tuning can reach ~96% success in **45–90 minutes of online fine-tuning** on real tasks — but that was with NVIDIA GPUs and a human safety supervisor (https://arxiv.org/abs/2502.05450). Everything ≥7B (π0, OpenVLA, GR00T, CogACT, UniVLA) needs LoRA + ≥22–27GB VRAM minimum for even the lightest adaptation — fine on a rented A100/4090, impossible on our AMD iGPU. **Bottom line: budget cloud GPU hours; openpi/LeRobot/GR00T all stream actions from a GPU policy server to the arm over a socket, so the iGPU laptop can be the robot controller while inference runs remotely.**

**Run:** Locally, SmolVLA is the only VLA that claims CPU inference, and nobody claims good iGPU inference — expect sluggish chunks; the async-inference stack (execute current chunk while the next is predicted) is what makes slow inference tolerable in practice. Closed models (Gemini Robotics VLA, Helix) can't be run at all; Gemini Robotics-ER 1.5 is reachable via API and is positioned as the "high-level brain" orchestrating a low-level policy — that's a System-1/System-2 pattern we can imitate with our own stack.

### Where does a tiny typed-decision model (Laya) beat a VLA — and where not?

**Laya wins on:**
- **Latency & footprint:** a typed-choice classifier returning probabilities + calibrated confidence runs in milliseconds on CPU with no GPU; every open VLA here is ≥0.45B params and (in practice) CUDA-bound. If the loop needs a decision every tick (grip now? retry? reset? intervene?), Laya is the only thing that runs natively on this machine.
- **Calibration & auditability:** VLAs emit action tokens/distributions with no calibrated confidence and no clean "I don't know" — RECAP had to train an explicit value function to know which actions are good (https://pi.website/blog/pistar06). Laya's calibrated confidence is directly usable as a gate: act when ≥0.8, flag a human/intervention when 0.5–0.8, stop when <0.5.
- **Data needs:** Laya trains from labeled decisions (a few hundred examples fine); VLAs want demo *trajectories* — even SmolVLA consumed ~10M frames for pretraining. On day-of, you can log decisions from runs and retrain Laya in minutes — a true same-day learning loop.

**VLA wins on:**
- **Generalisation:** VLAs transfer semantics to unseen objects/scenes from internet-scale pretraining; SmolVLA outperforms ACT baselines out-of-distribution on SO-101 (HF blog). Laya can't generalise beyond its state schema — no vision, no language.
- **Expressive control:** continuous, multimodal action distributions (diffusion/flow heads) that a typed-choice classifier cannot represent. Laya should never output joint commands.
- **Reasoning:** hierarchical VLM layers (Hi Robot, Gemini-ER) handle compound instructions and mid-run feedback; Laya has none.

**Where they compose (the hackathon move):** a small BC/ACT policy (or a SmolVLA on cloud GPU) as System 1, Laya as the calibrated supervisor that decides *continue / intervene / retry / escalate*, and the logged decisions become a graded dataset for the next training round — i.e., the RECAP stages (demo → correction → RL) implemented with a classifier as the value/criticism layer. Helix's trick of appending a "percent task completion" action (https://www.figure.ai/news/helix) is directly portable to a Laya-style head.

## Part C — Learning-loop methods (the theme)

Difficulty: ★ easy · ★★ moderate · ★★★ hard · ★★★★ research-grade, not for day-of.

- **Behaviour cloning.** Supervised imitation of (state, action) pairs from teleop. It is the substrate of everything else and is trainable on an SO-101 in minutes with LeRobot (`lerobot-train --policy.type=act`). Canonical open implementation: LeRobot (https://github.com/huggingface/lerobot). For a 1-day event: this is the default first loop — collect 30 min, train, deploy, repeat. ★
- **ACT — Action Chunking with Transformers** (Zhao et al., 2023; https://arxiv.org/abs/2304.13705 ; code https://github.com/tonyzhaozh/act ; in LeRobot as `act`). CVAE + transformer predicting action *chunks* with a temporal-ensemble; 80–90% success on fine tasks from **10 minutes** of demos — proven on SO-101-class arms. Best day-of bet after plain BC; gives the async/latency behaviour that makes slow inference survivable. ★★
- **Diffusion Policy** (Chi et al., RSS 2023; https://arxiv.org/abs/2303.04137 ; code https://github.com/real-stanford/diffusion_policy ; in LeRobot as `diffusion`). Represents multimodal action distributions via denoising diffusion; +46.9% avg over prior SOTA across 12 tasks in the paper. More compute per action than ACT; fine in sim, slower on CPU. ★★
- **VQ-BeT** (Park, Rybkin, Levine, ICML 2024; "Behavior Generation with Latent Actions", https://arxiv.org/abs/2403.03181 ; code https://github.com/jayLEE0301/vq_bet_official ; in LeRobot as `vqbet`). Discretises behaviour into latent tokens — handles multimodal prediction with ~5× faster inference than diffusion policies. Interesting because discrete *decision tokens* are conceptually close to Laya's typed choices. ★★★
- **DAgger** (Ross, Gordon, Bagnell, 2011; https://arxiv.org/abs/1011.0686). Roll the *learner*, label states with the expert, retrain — fixes covariate shift/compounding error. No robot needed to understand; to *run* it you need the intervention loop below. ★ (concept) / ★★★ (execution)
- **HG-DAgger** (Kelly et al., IROS 2019; https://arxiv.org/abs/1810.02890). The human intervenes only when *they* judge it unsafe — much more practical for humans; produces both recovery data and a risk metric. This is exactly what our SpaceMouse-overrides loop would be. ★★
- **Human-in-the-loop interventions as data collection.** SERL's own README recommends "providing interventions online during training… as easy as just touching the SpaceMouse" (https://github.com/rail-berkeley/serl). Verified adjacent papers: RaC — fine-tuning on human *recovery/correction* trajectories for long-horizon tasks (https://arxiv.org/abs/2509.07953); AIM — robot-gated requests for help via a learned Q-function (https://arxiv.org/abs/2506.09176); IntervenGen — synthesising corrective segments from a few interventions (https://arxiv.org/abs/2405.01472). **Note:** a specific MIT paper titled "Interventions" could not be verified and is not included. Laya is a natural *robot-gated* intervention trigger (its confidence = when to ask). ★★
- **SERL / HIL-SERL** (Berkeley RAIL; SERL https://arxiv.org/abs/2401.16013 , MIT code https://github.com/rail-berkeley/serl ; successor HIL-SERL https://hil-serl.github.io , implemented in LeRobot per its policy table: https://github.com/huggingface/lerobot). Real-world RL that trains in ~1 hour on contact-rich tasks by: BC pretraining → human interventions → RLPD offline RL. The canonical "loop converges in an afternoon" result — but assumes a Franka + GPU. ★★★
- **RL fine-tuning of (VLA) policies.** RLDG: distill specialist RL policies into a generalist by BC on RL rollouts (https://arxiv.org/abs/2412.09858 , https://generalist-distillation.github.io). ConRFT: offline+online consistency-policy RL for VLAs with human interventions, ~96% success in 45–90 min of online training (https://arxiv.org/abs/2502.05450). **RECAP** (π*0.6, PI, Nov 2025): RL with Experience and Corrections via Advantage-conditioned Policies — pretrain a value function over all data, then demos → teleop corrections → autonomous RL; more than doubled throughput and roughly halved failures on espresso/laundry/box-assembly (https://pi.website/blog/pistar06 , https://arxiv.org/abs/2511.14759). This is the field's current canonical "learning loop" — copy its staging even if you only run BC + interventions. ★★★★ (full versions) / ★★ (the demo→correction staging alone)
- **Sim-to-real via domain randomisation** (Tobin et al., 2017; https://arxiv.org/abs/1710.06437). Randomise visuals/dynamics in sim so reality looks "in-distribution". Day-of value is limited unless the event provides a sim; MuJoCo-based sim on CPU is feasible but policy transfer in 1 day is a stretch. ★★★
- **Real-to-sim evaluation — SimplerEnv** (https://github.com/simpler-env/SimplerEnv). Reconstructs real benchmark scenes in sim to evaluate policies cheaply; used as the eval harness by CogACT, UniVLA and GR00T's published checkpoints (verified in their READMEs). Useful to A/B policies without burning robot time. ★★★
- **Data flywheel / failure-driven data collection.** Verified instances: NVIDIA's GR00T-Mimic (scale existing demos with Cosmos Transfer-1) and GR00T-Dreams (generate new-task data from one image + instruction; NVIDIA reports N1.5 trained from Dreams data in 36 h) (https://developer.nvidia.com/blog/enhance-robot-learning-with-synthetic-trajectory-data-generated-by-world-foundation-models/ , https://nvidianews.nvidia.com/news/nvidia-powers-humanoid-robot-industry-with-cloud-to-robot-computing-platforms-for-physical-ai); Hugging Face's LeRobot Community Datasets — SmolVLA was pretrained on 487 community SO-100 datasets, and community pretraining lifted SO-100 success from 51.7% → 78.3% (https://huggingface.co/blog/smolvla). Host-relevant: Alloy's entire product is the fleet-data flywheel, and their `lerobot2mcap`/`tabular2mcap` tools (https://github.com/alloyrobotics) are literally ingest glue for it. **Note:** the paper the user mentioned as "Mitigating the Human-Robot Interaction Partition Problem" could not be found/verified and is not included. ★★ (we can log every run to LeRobot format and let failures drive the next collection batch)
- **Stall / failure detection & recovery.** No single canonical open-source "manipulation anomaly detection" implementation could be verified quickly; what *is* verified: Helix appends a "percentage task completion" action so the policy can self-terminate and be sequenced (https://www.figure.ai/news/helix); RECAP trains a value function that scores actions good/bad during deployment (https://pi.website/blog/pistar06); RaC explicitly trains recovery behaviours from interventions (https://arxiv.org/abs/2509.07953). A calibrated typed classifier (Laya) watching progress/probability is a defensible, honest day-of implementation of this layer. ★★
- **System 1 / System 2 escalation (fast policy + slow reasoner).** Verified lineage: SayCan — LLM grounds steps in affordances (https://arxiv.org/abs/2204.01691 , https://say-can.github.io); Inner Monologue — closed-loop replanning from embodied feedback (https://arxiv.org/abs/2207.05608 , https://innermonologue.github.io); Code as Policies — LLM writes robot policy code (https://arxiv.org/abs/2209.07753 , https://code-as-policies.github.io); VoxPoser — LLM composes 3D value maps (https://voxposer.github.io); RT-H — predicts "language motions" as an intermediate layer and *learns from language interventions* (https://arxiv.org/abs/2403.01823 , https://rt-hierarchy.github.io); Hi Robot (Physical Intelligence/Stanford, ICML 2025) — VLM reasons over complex prompts + live human feedback ("that's not trash"), a low-level VLA executes (https://arxiv.org/abs/2502.19417 , https://www.pi.website/research/hirobot); Figure Helix — S2 7B VLM @7–9 Hz conditioning S1 80M policy @200 Hz (https://www.figure.ai/news/helix); Gemini Robotics 1.5 = ER-1.5 orchestrator + VLA executor (https://deepmind.google/blog/gemini-robotics-15-brings-ai-agents-into-the-physical-world). For us: Codex/ER-style slow loop + ACT fast loop + Laya as the escalation gate is a coherent System1/2 story. ★★
