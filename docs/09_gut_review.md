# 09 — GUT, reviewed and reflected (and why it powers this repo's core loop)

*gut.qalarc.com · github.com/qalarc/gut-finetuned · HF Qalarc/Laya-GUT-Finetune ·
local: `~/projects/GLM_projects/Laya_integrations/` (read-only for us)*

## What GUT is

**Guided Unconscious Thinking** — a disciplined pipeline for turning a big model's
judgement into a small, calibrated, locally-served decision model ("Laya"):
**collect → normalize → train (RLCD) → gate → register → serve**, with a typed
"System One" row contract (`state`, `questions{type,instructions,criteria}`,
soft `answers`, `source`, `ts`) and a hard gate law:

> held-out teacher-agreement **≥ 0.85** AND calibration **ECE ≤ 0.10** AND no label
> receiving <5% probability on >20% of examples. No pass, no register. No exceptions.

Serve: `POST :8798/v1/systemone` with `X-Laya-Domain` — one URL flips any app from
cloud to local. Currently ~29 domains (1.5k–16k rows each), 10 registered checkpoints.

## What worked (keep)

1. **The gate law.** Calibration as a first-class, non-negotiable criterion is the
   single best decision in the project. A classifier that says "stalled, p=0.91"
   is only useful if 0.91 means 91%.
2. **Frozen criteria.** Byte-identical question shapes per domain; drift trains one
   question and serves another (the gmux bug). We inherit this verbatim:
   `control/robot_ops.schema.json` is stamped `criteria_version: 2026-11-24.1` and
   must never change after row #1.
3. **Soft labels.** Distributions beat hard labels — they preserve the teacher's
   hedging. Our stall rows use them (`0.7·S2 root cause + 0.3·S1 spread`).
4. **Cheap-first collection ladder** (Jev-shadow → agent-logged → human → traces) and
   honest failure: 10 of 12 domains currently FAIL the gate (mostly ECE ≈ 0.5), and
   that is treated as a valid, useful outcome. Rare and right.
5. **Operational humility:** ~250 rows for an honest r1, 1.5k+ for calibration;
   "operational outcomes are first-class options, not failures" (`insufficient_evidence`
   in cup-origin ≈ our `controller_error`/`none` heads).

## What didn't (avoid on the day)

1. **Calibration is the bottleneck, not accuracy.** Most domains hit agreement but
   fail ECE. The winning trick so far is `--polish-epochs 1` confidence-transfer
   (cup-origin, derm-triage passed that way). Plan for it: budget a polish epoch.
2. **Dataset shape drift is silent poison** — happened twice (gmux). Our defence: rows
   are generated by ONE code path (`to_dataset_row`) from the frozen schema, never
   hand-written.
3. **Row count ≠ readiness.** 16k trading rows still fail; 1.75k cup rows pass. Narrow,
   honest, well-shaped > big and muddy. Our `robot-ops` domain is deliberately narrow:
   one arm, few scenarios, 7 failure labels.
4. **Serving reality on this box:** ~2.5 s/decision CPU-class latency (we measured
   1.35 s warm for our probe) → System 1 is an *on-stall/heartbeat* organ here, not a
   per-tick one. Design around latency; don't fight it.

## GUT → this hackathon, mapped

| GUT concept | here |
|---|---|
| System One row | `data/robot-ops.jsonl` (written by the stall controller, one code path) |
| teacher | System 2 (local GLM) + outcome ground truth |
| gate | agreement ≥0.85, ECE ≤0.10 before the `robot-ops` checkpoint is served |
| register/serve | Laya_integrations registry; `X-Laya-Domain: robot-ops` |
| flywheel | stall → S2 recovers → label → retrain → S1 catches it next time → escalation rate falls |
| FAIL-is-valid | if the day's checkpoint doesn't gate, show the untrained-vs-trained curve honestly |

## The reflection, in one paragraph

GUT spent months proving that *small calibrated decision models are buildable but only
as fast as their label discipline*. This hackathon is the first time the flywheel gets a
bounded, honest, high-signal domain: a robot that stalls for a reason a 30B reasoner can
diagnose and a tiny model can learn to recognise. If `robot-ops` gates by 18:30 on
5 Dec, that's GUT's thesis demonstrated in miniature, on stage, in one day — and if it
doesn't, the falling-escalation curve still is.
